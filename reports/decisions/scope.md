## DEC-001: 1차 대상 호선과 학습 모델

- 상태: 승인
- 날짜: 2026-11-02
- 결정자: 사용자
- 범위: 2024~2025년 2호선, 랜덤포레스트·MLP·LSTM 세 학습 모델

### 설명한 선택 근거

랜덤포레스트는 표 형태의 조건 관계, MLP는 기본 신경망의 비선형 학습, LSTM은 시간 순서 처리의 효과를 비교하기 위한 후보로 설명했습니다. 시간순 입력 처리 여부, 데이터 규모와 과적합, 설정 복잡성의 차이를 안내했습니다. Ridge·GRU·부스팅·1차원 CNN은 추가 후보로 소개했으나 이번에는 확정하지 않았습니다.

### 실제 사용자 답변

> 그럼 1차는 2호선으로 하고 랜덤포레스트, MLP, LSTM으로 진행하는데 왜 이 모델들을 선정하는지 더 추가할 모델은 없는지 알려줄래?

설명 후 최종 확인:

> 그럼 일단 세 모델로 진행하는 걸로 하자. 하나하나 차근차근 알려주면서 진행해줄래?

### 승인 범위와 다음 단계

위 대상과 세 모델의 비교 방향에 대한 승인입니다. 구체적인 예측 시점·출력, 입력 기간·변수, 분할, 지표, 하이퍼파라미터·손실 가중치 승인은 포함하지 않습니다. 학습은 아직 실행하지 않았습니다.

다음은 예측 시점과 출력 정의부터 한 항목씩 설명하고 확인합니다. 이후 입력, 평가 설계, 모델별 설정 순으로 협의합니다. 기존 데이터 검증 작업은 별도 `data/validate-inputs` 브랜치에 있습니다.

## DEC-002: 예측 시점과 출력

- 상태: 승인
- 날짜: 2026-11-02
- 결정자: 사용자

### 결정

오늘 23~24시까지의 기록이 확보되었다고 가정하고 다음 날 06~24시의 18개 시간대별 승차·하차, 총 36개 값을 예측합니다. 랜덤포레스트·MLP·LSTM 모두 동일한 예측 대상을 사용합니다. 예측 대상일의 실제 승하차를 입력하지 않습니다.

### 설명한 장단점

다음 날 운영 준비라는 목적과 연결되고 하루 수요 곡선·경기 전후 피크를 비교하기 쉽습니다. 당일 관측으로 예측을 갱신하지 않으므로 돌발 상황 반영에는 한계가 있습니다. 매시간 다음 한 시간을 예측하는 대안은 최신 관측 활용이 가능하지만 구현과 데이터 가용성 조건이 달라집니다.

### 승인 근거

다음 날 36개 값 예측 방식 제안에 사용자가 답변했습니다.

> 응 그 방식으로 진행하자. 과거 며칠의 기록을 입력하는 게 좋을지 장단점이랑 같이 설명해줘.

### 한계와 미확정

실제 데이터 공개 시점은 검증하지 않았습니다. 우선 과거 자료를 이용한 모의 예측 실험입니다. 과거 입력 기간, 입력 표현과 부가 변수, 모델별 출력 구현, 분할·지표·학습 설정은 이번 승인 범위에 포함하지 않습니다.

## DEC-003: 과거 입력 기간 3일·7일·14일 비교

- 상태: 승인
- 날짜: 2026-11-02
- 결정자: 사용자

### 결정

랜덤포레스트·MLP·LSTM 각각 과거 3일·7일·14일을 입력하는 총 9개 기본 조합을 비교합니다. 특정 기간을 최선으로 미리 확정하지 않습니다.

### 선택 근거와 장단점

- 3일: 최근 변화에 집중하고 입력이 작지만 지난주 같은 요일 기록이 없습니다.
- 7일: 일주일의 요일 구성을 포함하지만 같은 요일 관측은 한 번입니다.
- 14일: 같은 요일을 두 번 포함하지만 입력과 계산 부담이 커지고 불필요한 정보가 늘 수 있습니다.
- 세 기간을 비교하면 모델마다 필요한 과거 길이가 다른지 검증할 수 있습니다. 단, 성능 차이를 주간 주기의 효과만으로 단정하지 않습니다.
- 기본 조합이 9개로 늘어나므로 실행·분석 비용이 증가합니다. 경기 정보 포함/제외나 반복 시드는 이번 결정에 포함하지 않습니다.

### 사용자 승인

> 좋아. 3일·7일·14일 모두 비교하는 걸로 기록하고 커밋해줘. 다음으로 결정해야 할 건 뭐야? 장단점이랑 같이 설명해줘.

### 비교 설계 원칙

같은 대상 날짜·정보·평가 지표를 사용하도록 설계합니다. 입력 기간 외 주요 설정은 모델 내에서 가능한 한 동일하게 맞추고, 입력 크기에 따른 파라미터 수 차이를 기록합니다. 먼저 한 조합의 데이터 흐름을 점검한 뒤 나머지 조합에 적용합니다. 초기 점검에 사용할 설정도 사전 협의 대상입니다.

### 미확정

학습·검증·최종 평가 날짜, 선택 지표, 입력 변수·결측 처리, 모델별 하이퍼파라미터·시드·손실 가중치는 아직 결정하지 않았습니다. 모델 학습은 실행하지 않았습니다.

## DEC-004: 시간순 분할과 기록 없는 날짜의 상태

- 상태: 승인
- 날짜: 2026-11-02
- 결정자: 사용자

### 결정

| 구간 | 예측 대상 날짜 |
|---|---|
| 학습 | 2024-01-01~2024-12-31 |
| 검증 | 2025-01-01~2025-06-30 |
| 최종 평가 | 2025-07-01~2025-12-31 |

세 모델·세 입력 기간의 비교 날짜는 공통으로 맞춥니다. 14일의 과거 기록 확보를 위해 학습 대상은 2024-01-15부터 시작합니다. 최종 평가에서는 기존 탐색 날짜 2025-09-25·26·27·28·30 및 2025-10-01을 별도 분리합니다. 추가 제외 전 대상 수는 학습 352일, 검증 181일, 평가 178일입니다.

분할은 예측 대상 날짜 기준입니다. 검증·평가 대상일보다 과거인 이전 구간의 관측은 입력으로 사용할 수 있습니다. 기존 탐색일의 과거 관측도 이후 날짜 예측 시 이미 알려진 기록으로 사용할 수 있으나 탐색일 자체는 최종 성능 집계에서 제외합니다. 전처리 기준은 학습 구간에만 맞춥니다.

**경기 기록이 없는 날은 미확인으로 유지합니다.** 이를 경기 없음 또는 비시즌으로 확정하거나 임의로 0으로 대체하지 않습니다. 미확인 상태의 구체적인 모델 입력 표현·결측 처리 방법은 별도 협의합니다.

### 승인 근거

시즌 구성·상태별 날짜 수와 분할의 장단점을 설명한 뒤 사용자가 답변했습니다.

> 응 그 분할로 확정하고 기록해줘. 경기 기록 없는 날은 미확인으로 남겨두고, 다음으로 결정해야 할 것도 장단점이랑 같이 설명해줘.

### 근거와 한계

[검토 보고서](../data_review.md#split-review)를 참고합니다. 각 구간에 경기 결과 기록일과 겨울 구간이 있으나 검증과 평가의 계절 구성은 다릅니다. 시즌 라벨과 원천 일정의 완전성은 아직 미검증입니다. 경기 상태는 사후 평가용 정보와 예측 당시 사용 가능한 정보를 구분해야 합니다.

### 미확정

모델 선택 지표, 상태별 집계·가중치, 입력 변수와 미확인 표현, 하이퍼파라미터·초기화·시드·손실 함수, 최종 모델 재학습 절차는 아직 승인하지 않았습니다. 학습은 실행하지 않았습니다.

## DEC-005: 야구 중심 1차 실험과 향후 행사 확장

- 상태: 승인
- 날짜: 2026-11-02
- 결정자: 사용자

### 결정

1차는 현재 확보한 야구 자료를 중심으로 빠르게 비교합니다. 콘서트·다른 행사 정보 추가는 향후 발전 계획으로 분리하며 이번 필수 실행 범위에 포함하지 않습니다. 기존의 2호선·2024~2025년·세 모델·세 입력 기간·시간순 분할은 유지합니다.

### 사용자 답변

> 응응 야구로만 빠르게 돌리고 다른 정보들을 추가하는 식으로 가려고 향후 발전 계획에 넣을 생각이라 괜찮을 거 같아.

### 해석과 한계

'야구 중심'은 이번에 활용할 행사 정보의 범위를 뜻합니다. 학습·검증·평가 날짜를 야구 경기일만으로 제한한다는 의미가 아닙니다. 기존에 합의한 전체 날짜와 기록 없는 날의 미확인 상태를 유지합니다.

향후 행사 종류·장소·예정 시각 등을 확보해 확장하고 해당 행사에서 별도 평가합니다. 야구 데이터의 결과만으로 콘서트 등에서 성능이 검증됐다고 주장하지 않습니다. 행사 정보 포함·제외 추가 실험은 아직 확정하지 않았습니다.

평가 지표는 전체 검증 날짜의 승차·하차 평균 MAE를 주 지표, RMSE와 월별·경기 상태별 결과를 보조로 제안한 상태입니다. 본 기록은 확장 범위 합의이며 평가 기준·학습 손실·파라미터에 대한 별도 승인을 대신하지 않습니다.

## DEC-006: 모델 선택 지표 A안

- 날짜: 2026-11-02
- 상태: 사용자 선택 완료 / 팀 검토 대기 / 학습 실행 승인 전

### 선택

2025년 상반기 공통 검증 날짜의 원래 인원 단위에서 다음 점수를 계산합니다.

`selection_score = (boarding_MAE + alighting_MAE) / 2`

각 MAE는 동일한 날짜의 18개 시간대 전체 절대오차 평균입니다. 점수가 낮은 모델·입력 기간 조합을 우선 선택합니다. 승차·하차 RMSE, 월별 및 note 상태별 성능·표본 수는 함께 보고하되 사후에 주 지표를 바꾸지 않습니다. 미확인일도 이용량 정답이 있으면 전체 평가에 포함합니다.

### 근거와 한계

평균 몇 명 틀리는지 설명하기 쉽고 야구 외 행사로 확장할 때도 동일한 기준을 사용할 수 있습니다. MAE 자체가 새로운 행사에서의 일반화를 보장하지는 않습니다. 일부 큰 오차가 전체 평균에 가려질 수 있어 보조 지표를 함께 봅니다.

### 사용자 답변

> A로 가야 확장하기 좋은거니까 A로 가자

### 승인 범위

평가 기준에 대한 사용자 선택입니다. 팀 검토 후 내일 실행하는 일정에 따라 아직 학습하지 않습니다. 학습 손실·조기 종료 지표·가중치·동점 처리·모델 설정은 별도 협의합니다.
