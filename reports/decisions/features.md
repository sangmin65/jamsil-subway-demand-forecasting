## DEC-007: 요일·월·공휴일 입력

- 날짜: 2026-11-02
- 상태: 사용자 선택 완료 / 팀 검토 대기 / 학습 미실행

사용자는 1차부터 공휴일을 포함하는 B안과 제시된 정의에 '응응'으로 동의했습니다. 예측일의 요일·월·is_holiday를 사용합니다. 연휴 전후 변수는 이번 범위에 넣지 않습니다. 범주 인코딩은 별도 협의합니다.

### is_holiday 정의

지정된 공휴일·대체공휴일·임시공휴일·전국 단위 공휴 선거일은 1, 그 외는 0입니다. 평범한 토·일요일은 0이며 요일로 구분합니다. 이는 모델용 변수의 정의이며 일요일까지 포함하는 법적 공휴일 전체 정의와 다릅니다. 2024~2025년 제헌절과 회사별 휴무·개인 연차는 포함하지 않습니다.

### 확인 자료

[달력 JSON](../../data/reference/holidays_2024_2025.json)에 날짜별 출처를 기록했습니다. 기본 날짜는 한국천문연구원 [2024 달력](https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2024), [2025 달력](https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2025)의 공휴일 표와 대조했습니다. 일반 일요일은 제외합니다.

- 2024-10-01: 인사혁신처 2024-09-03 지정안 의결 발표를 확인했습니다. 해당 발표일은 최종 관보 공고일과 구분합니다.
- 2025-01-27: 인사혁신처 2025-01-15 지정 공고 확인.
- 2025-06-03: 정부 2025-04-08 선거일·임시공휴일 지정 발표 확인.

세 날짜 모두 전날 예측보다 먼저 발표됐습니다. 정기 달력의 최초 공개일은 JSON에 추정값을 넣지 않았습니다. 임시공휴일 출처는 각 JSON 행에 있습니다.

각 연도 19개 고유 날짜, 총 38개입니다. 2025-05-05의 두 공휴일은 한 날짜로 집계합니다. 날짜 중복 없음 및 임시 지정 발표일의 시간 순서를 검사했습니다. 원본 승하차 표에는 아직 결합하지 않았고 모델을 학습하지 않았습니다.

## DEC-008: 기본 일정과 홈팀·원정팀 입력

- 날짜: 2026-11-02
- 상태: 사용자 선택 완료 / 팀 검토 대기 / 학습 미실행

### 선택한 입력

과거 승하차와 달력 입력에 다음 야구 정보를 추가합니다.

- 수집 기록 유무(`has_kbo_record`)와 건수(`listed_game_count`)
- 경기 기록 1·2의 예정 시작 시각
- 경기 기록 1·2의 홈팀·원정팀

시각·팀의 인코딩, 빈 시각의 계산용 대체값 등 구체적인 표현은 다음 협의 대상입니다. 시각의 여러 중복 표현이나 복수 기록 플래그를 자동으로 모두 추가하지 않습니다.

### 제외와 의미

별도 인기도 점수·팀별 임의 가중치는 사용하지 않습니다. 홈팀은 잠실 홈 구단(LG·두산)을 구분하고 원정팀은 상대 구단을 구분하는 정보입니다. 학습된 차이를 인기도의 인과 효과로 해석하지 않습니다.

note는 사후 상태 분석에 사용하고 모델 입력에서 제외합니다. gamecenter_status, 예측 대상일의 실제 관중·점수·시작/종료 시각, 검증·관리용 열도 입력에서 제외합니다.

has_kbo_record=0은 실제 경기 없음이 아니라 수집 목록에 기록 없음입니다. 건수에는 취소 기록이 포함됩니다. 번호 1·2는 예정 시각 순서이며 공식 경기 번호가 아닙니다. 전날 일정 가용성은 아직 검증되지 않았으므로 사후 수집 일정에 기반한 실험이라는 한계를 명시합니다.

### 사용자 확인

'기본 일정 + 홈팀·원정팀, 인기도 점수 제외' 제안에 사용자가 '응 그게 좋을거 같아'라고 답했습니다. 잠실 홈팀 구조에 대한 추가 설명 후 'ㅇㅋ 그럼 진행해도 될 거 같아.'로 확인했습니다.

실제 모델 학습은 전체 설정 결정과 팀 검토 후 진행합니다.

## DEC-009: 예정 시작 시각과 정보 존재 표시

- 날짜: 2026-11-02
- 상태: 사용자 선택 완료 / 팀 검토 대기 / 학습 미실행

### 결정

경기 기록 1·2 각각 예정 시작 시각을 자정부터의 분으로 표현하고 시각 정보 존재 여부를 함께 제공합니다. 예: 18:30은 1110분과 존재 표시 1. 빈 시각은 계산용 0과 존재 표시 0입니다. 원본 CSV는 수정하지 않고 이후 모델 입력 생성 단계에서 적용합니다.

빈 시각의 0은 실제 자정 경기·경기 없음·취소를 뜻하지 않습니다. 수집 기록 유무·건수와 함께 해석하고 원본의 미확인 상태를 보존합니다. 기록 한 건이면 둘째 시각 정보가 없고, 기록 자체가 없으면 두 시각 정보가 없습니다.

### 사용자 확인

예정 시각의 분 변환, 빈 시각의 계산용 0과 존재 표시, 정규화와의 차이를 설명한 뒤 사용자가 답했습니다.

> 음 확인했어 넣어도 좋을거 같아

### 미확정 범위

분 값을 1440으로 나누는 방식은 설명용 후보이며 아직 승인하지 않았습니다. 팀·달력 범주 인코딩, 학습 손실·모델 설정도 별도 협의합니다. 본 승인을 팀 원-핫 인코딩 승인으로 확대하지 않습니다. 추가 상대 시각 열(`minutes_until_scheduled_start`)은 아직 입력으로 확정하지 않았습니다.

일정의 예측 전날 가용성이 미검증이라는 기존 한계는 유지합니다. 전체 설정의 팀 검토 후 학습합니다.

## DEC-010: 팀 이름 원-핫 인코딩

- 날짜: 2026-11-02
- 상태: 사용자 선택 완료 / 팀 검토 대기 / 학습 미실행

### 결정

경기 기록 1·2 각각의 홈팀·원정팀을 원-핫 인코딩합니다. 네 필드는 구분하며 세 모델에 같은 범주 정의를 제공합니다. 팀에 임의의 순위·인기도 점수를 부여하지 않습니다.

범주 목록은 학습 자료에서만 구성합니다. `NO_LISTED_RECORD`는 기록 없음 범주로 유지하고, 학습에 등장하지 않은 팀은 별도의 새 범주로 처리합니다. 새 범주와 기록 없음은 구분합니다. 검증·평가 데이터를 보고 범주 목록을 확장하지 않습니다.

### 근거와 한계

팀별 구분에 수치적 크기·간격을 부여하지 않고 해석하기 쉽습니다. 대신 입력 열이 늘며, 새 범주에 대한 별도 학습 사례가 없다면 예측 품질은 보장되지 않습니다. 원-핫 인코딩만으로 드문 팀 조합의 과적합이 해결되는 것은 아닙니다.

### 사용자 답변

> 응 원핫 인코딩으로 가자

팀 범주 표현에 대한 결정입니다. 달력 표현·정규화·모델 구조·손실·학습 설정은 별도 협의하며 전체 설정의 팀 검토 후 실행합니다.

## DEC-011: 요일·월 원-핫 인코딩

- 날짜: 2026-11-02
- 상태: 사용자 선택 완료 / 팀 검토 대기 / 학습 미실행

### 결정

예측일의 요일은 월~일 7개 범주, 월은 1~12월 12개 범주로 원-핫 인코딩합니다. 달력 입력은 이 19개 값과 공휴일 여부 0·1을 합친 20개 값입니다. 범주는 달력의 고정 정의이며 검증·평가 데이터에서 추정하지 않습니다.

순환(sin/cos) 인코딩은 이번 초기 설정에 사용하지 않습니다. weekday_name, is_weekend, year, day를 별도 입력으로 자동 추가하지 않습니다. 사용하기로 한 달력 정보는 요일·월·공휴일입니다.

### 이유와 한계

각 요일과 월의 차이를 순서·거리 가정 없이 구분하며 설명이 쉽습니다. 총 19개 범주 열이 필요하고, 일요일~월요일 및 12월~1월의 연결을 직접 표현하지 못하는 한계가 있습니다. 필요하면 후속 실험에서 순환 표현과 비교합니다.

### 사용자 답변

> 원핫으로 진행해줘

전체 설정의 팀 검토가 끝난 뒤 학습합니다. 정규화·모델 구조·학습 설정은 별도 협의합니다.

## DEC-012: LSTM의 시간대별 과거 입력

- 날짜: 2026-11-02
- 상태: 사용자 선택 완료 / 팀 검토 대기 / 학습 미실행

### 결정

LSTM은 과거 승차·하차 기록을 날짜와 시간대의 오름차순으로 읽는 A안을 사용합니다. 관측 시간대 한 구간이 한 시점이며, 각 시점에는 승차·하차 2개 값이 들어갑니다.

| 과거 기간 | 시점 수 | 시점별 값 |
|---|---|---|
| 3일 | 54 | 승차·하차 2개 |
| 7일 | 126 | 승차·하차 2개 |
| 14일 | 252 | 승차·하차 2개 |

하루에는 06~24시의 18개 관측 구간이 있습니다. 23~24시 다음 시점은 다음 날 06~07시이므로, 이 배열을 24시간 연속 관측이라고 설명하지 않습니다. 미관측 00~06시를 실제 인원 0으로 채우지 않습니다.

예측 대상은 DEC-002대로 다음 날 18개 시간대의 승차·하차, 총 36개 값입니다. 시간대 식별자 등 추가 입력은 이번 결정으로 자동 추가하지 않습니다.

### 이유와 한계

시간대 사이의 이용량 변화와 날짜를 넘는 패턴을 순차적으로 학습하도록 합니다. 하루를 한 시점의 36개 값으로 묶는 B안보다 시퀀스가 길어져 계산 부담과 긴 의존관계 학습의 어려움이 커질 수 있습니다. 3·7·14일 비교에서 실제 검증 성능과 학습 시간을 확인합니다.

B안도 출력층을 36개 값으로 구성하면 시간대별 예측이 가능합니다. A안 선택의 근거는 시간대별 출력의 가능 여부가 아니라 과거 기록을 시간대별 순서로 학습하는 방식입니다.

### 사용자 답변

> A안 무조건 A안 시간대 별로 읽어야 시간대 별로 추정이 가능하지

시간대별 읽기 선택을 기록하며, B안도 시간대별 출력이 가능하다는 점을 설명했습니다. 예측일 달력·경기 정보의 결합 위치, 출력층 구성, 정규화, 모델 크기와 학습 설정은 별도 협의합니다. 전체 설정과 팀 검토가 완료되기 전 학습하지 않습니다.

## DEC-013: LSTM 과거 요약 후 예측일 정보 결합

- 날짜: 2026-11-02
- 상태: 사용자 선택 완료 / 팀 검토 대기 / 학습 미실행

### 결정

1차 LSTM은 과거 시간대별 승차·하차를 읽은 결과에 예측일 달력·경기 정보를 결합하는 A안을 사용합니다. 결합된 정보를 최종 예측 부분에 전달해 다음 날 시간대별 승차·하차를 예측합니다. 과거 입력 순서는 DEC-012를 따릅니다.

여기서 A/B는 부가 정보의 결합 위치를 뜻하며, DEC-012의 시간대별/날짜별 읽기 선택과 별개입니다.

### 이유와 한계

과거 이용량 처리와 예측일 조건의 역할을 구분해 설명하기 쉽고, 향후 다른 행사 정보를 결합 부분에 추가하기 수월합니다. 다만 LSTM이 과거 기록을 읽는 과정 자체에는 예측일 조건이 직접 입력되지 않습니다. 과거 요약은 단순 평균이 아닌 학습된 표현이며 경기 효과를 사람이 정한 가중치로 더하지 않습니다.

### 후속 비교 후보

B안은 동일한 예측일 달력·경기 정보를 모든 과거 시점에 반복해서 붙여 LSTM에 입력합니다. 예측일 조건이 과거 기록의 처리 과정부터 영향을 줄 수 있지만 입력 차원이 늘어납니다. 과거 해당 날짜의 경기 정보를 추가하는 것과는 다른 실험입니다.

후속 비교에서는 동일한 데이터 분할·대상 날짜·입력 정보·과거 기간·평가 지표를 사용하고, 합의한 학습 조건을 가능한 한 맞춥니다. 결합 위치에 따라 파라미터 수가 달라질 수 있으므로 모델 크기와 학습 시간도 기록합니다. A/B 선택·튜닝은 검증 자료로 수행하며 최종 평가 자료로 반복 선택하지 않습니다.

B안은 후속 실험 후보로 기록하며 이번 9개 기본 조합에 자동 추가하거나 실행하지 않습니다. 구체적인 비교 범위와 설정은 실행 전 별도 협의합니다.

### 사용자 답변

> A안으로 진행하고 후속으로 B안으로 비교군도 가능하다는거지?

정규화, 출력층 구성, 모델 크기, 손실 함수와 학습 설정은 미정입니다. 설정 전체와 팀 검토 완료 후 학습합니다.

## DEC-014: 1차 신경망 과거 승하차 입력 표준화

- 날짜: 2026-11-02
- 상태: 사용자 선택 완료 / 팀 검토 대기 / 학습 미실행

### 결정

1차 MLP·LSTM의 과거 승차·하차 입력은 승차와 하차를 각각 표준화합니다. 변환은 `(인원 - 학습 평균) / 학습 표준편차`입니다. 평균·표준편차는 2024년 학습 자료에서만 계산하고, 검증·평가 자료에는 저장한 기준을 그대로 적용합니다. 시간대별 별도 스케일러를 자동 추가하지 않습니다.

이번 승인은 과거 승하차 입력에 한정됩니다. 예측 정답의 변환, 예정 시각 등 다른 수치 입력의 스케일, RF 전처리, 손실 함수·가중치는 별도 협의합니다. 구체적인 스케일러 적합 대상 행과 중복 처리 등 구현 기준은 실행 전에 명시합니다.

### 근거와 한계

읽기 전용 확인에서 2024년 2호선 원본 366일·6,588행의 승차 중앙값은 435명, 최대는 13,775명이며, 하차 중앙값은 432명, 최대는 10,468명입니다. 최솟값은 각각 19명·58명으로 해당 범위에는 0명이 없습니다. 이는 분포 설명용 통계이며 실제 스케일러를 적합하거나 적용한 결과가 아닙니다.

표준화는 원래 인원 차이의 선형 관계를 유지하면서 신경망 입력 크기를 조정하는 초기 기준입니다. 큰 값이 평균·표준편차에 영향을 주고, 표준화 후에도 비대칭 분포와 큰 값은 남습니다. 정규분포로 바꾸는 처리가 아닙니다. 큰 값이라는 이유로 삭제·상한 절단하지 않습니다.

로그 변환 후 표준화는 후속 비교 후보입니다. 0의 유무와 로그 변환의 필요성은 별개입니다. 초기 검증 결과와 오차를 확인한 뒤 필요하면 사전 협의하여 비교하고, 전처리를 변경하면 모델도 다시 학습합니다. 최종 평가 자료로 전처리를 반복 선택하지 않습니다.

### 사용자 답변

> 응 그럼 일단 1차는 표준화로 진행하자

설정 전체 결정과 팀 검토 완료 후 학습합니다. 이번에는 결정 문서만 갱신합니다.

## DEC-015: 예측 정답의 원래 인원 단위 유지

- 날짜: 2026-11-02
- 상태: 사용자 선택 완료 / 팀 검토 대기 / 학습 미실행

### 결정

1차 실험의 예측 정답인 다음 날 시간대별 승차·하차 36개 값은 원래 인원 단위를 유지합니다. 정답에 표준화나 로그 변환을 적용하지 않습니다. MLP·LSTM의 과거 입력은 DEC-014에 따라 승차·하차 각각 표준화하므로 입력과 정답의 처리를 구분합니다.

예측값은 인원 단위로 해석하며 정답 스케일의 역변환은 필요하지 않습니다. 출력층 활성화, 음수 예측 처리, 반올림 여부는 이번 결정에 포함하지 않습니다.

### 이유와 한계

선택 지표인 원래 인원 단위의 승차·하차 평균 MAE와 학습 오차의 관계를 설명하기 쉽습니다. 다만 이 결정 자체가 MAE 손실이나 승차·하차 손실 가중치를 승인한 것은 아닙니다. 손실 함수에 따라 큰 오차의 반영 방식이 달라집니다.

신경망은 수천~수만 단위의 출력을 학습해야 하므로 수렴 속도와 학습 안정성을 확인합니다. 입력 표준화만으로 출력 규모에 관한 어려움이 모두 해결된다고 가정하지 않습니다. 정답 변환을 나중에 비교할 필요가 생기면 사전 협의 후 재학습하고 검증 자료로 판단합니다.
