# 경기 결합표 데이터 사전

출처: 2026-11-02 사용자가 전달한 팀원 설명. 수집 코드·공식 일정 전수 대조를 완료했다는 의미는 아닙니다. 아래 의미를 기록하며 실제 모델 입력 변수는 별도 협의합니다.

## 대상과 정답

| 열 | 의미 |
|---|---|
| 날짜 | 승하차를 예측할 대상 날짜 |
| 호선 | 대상 노선: 2호선·9호선. 이번 실험은 2호선 |
| 역명 | 종합운동장역 |
| 시간대 | 인원이 집계된 1시간 구간 |
| 승차인원 | 해당 날짜·호선·시간대의 실제 승차 인원: 정답 |
| 하차인원 | 해당 날짜·호선·시간대의 실제 하차 인원: 정답 |

같은 예측 대상 행의 승차·하차 정답을 입력에 넣지 않습니다. 예측일 이전 날짜의 실제 인원은 합의된 과거 창을 구성하는 데 사용할 수 있습니다.

## 달력

| 열 | 의미 |
|---|---|
| year | 연도 |
| month | 월 |
| day | 월중 날짜 |
| hour | 시간대 시작 시각. 18~19시는 18 |
| weekday | 월=0, 화=1, 수=2, 목=3, 금=4, 토=5, 일=6 |
| weekday_name | 한글 요일 |
| is_weekend | 토·일=1, 나머지=0. 공휴일 여부와 다름 |

## 경기 기록

| 열 | 의미 |
|---|---|
| has_kbo_record | 해당 날짜 기록이 수집 목록에 있으면 1, 없으면 0. 실제 경기 개최 여부가 아님 |
| listed_game_count | 해당 날짜 수집 기록 수. 취소 기록 포함 |
| has_multiple_listed_games | 수집 기록이 2건이면 1, 그 외 0. 실제 두 경기 개최 여부가 아님 |
| scheduled_start_time_1 | 첫 번째 기록의 예정 시작 시각 |
| scheduled_start_minutes_1 | 자정부터 예정 시작까지의 분. 18:30=1110 |
| minutes_until_scheduled_start_1 | 예정 시작 분 - 해당 시간대 시작 분. 양수는 시작 전, 음수는 시작 이후 |
| home_team_1 | 첫 번째 기록의 홈팀 |
| away_team_1 | 첫 번째 기록의 원정팀 |
| scheduled_start_time_2 | 두 번째 기록의 예정 시작 시각 |
| scheduled_start_minutes_2 | 두 번째 기록의 예정 시작을 자정부터 분으로 변환 |
| minutes_until_scheduled_start_2 | 두 번째 예정 시작 분 - 해당 시간대 시작 분 |
| home_team_2 | 두 번째 기록의 홈팀 |
| away_team_2 | 두 번째 기록의 원정팀 |

번호 1·2는 예정 시작 시각 순서이며 공식 경기 번호가 아닙니다. 해당 기록이 없으면 시간은 빈칸, 팀은 `NO_LISTED_RECORD`입니다. 이 표시를 실제 경기 없음으로 바꾸지 않습니다.

예정 시작 시각이라는 열의 의미와 예측 전날 그 일정이 공개돼 있었다는 검증은 별개입니다. `minutes_until_scheduled_start`는 예측 대상 시간대와 예정 시각 사이의 계산값이며 실제 경기 진행 여부가 아닙니다.

## 검증·관리 전용: 모델 입력에서 제외

| 열 | 의미 |
|---|---|
| schedule_record_status | 아래 수집 상태 분류 |
| schedule_completeness_verified | 수집 목록의 완전성 검증 여부. 현재 모두 0: 미검증 |
| schedule_snapshot_verified | 예측 전날까지 공개된 일정인지 검증 여부. 현재 모두 0: 미검증 |

- `listed`: 해당 날짜 기록 있음.
- `no_record_in_collected_month`: 같은 연도·월에 기록은 있으나 해당 날짜 기록 없음. 그 월을 빠짐없이 수집했다는 보장이 아님.
- `outside_collected_months`: 해당 연도·월의 기록 자체가 없음. 비시즌 확정값이 아님.

검증용 열은 추적·품질 검사·집계에 보존하되 모델 입력에서 제외합니다. 0은 오류 확인이 아니라 검증되지 않았다는 의미입니다.

## 과거 이용량

| 열 | 의미 |
|---|---|
| board_lag_1d | 같은 호선·시간대의 전날 실제 승차 |
| alight_lag_1d | 같은 호선·시간대의 전날 실제 하차 |
| board_lag_7d | 같은 호선·시간대의 7일 전 실제 승차 |
| alight_lag_7d | 같은 호선·시간대의 7일 전 실제 하차 |

합의된 3일·7일·14일 실험은 전체 과거 창을 구성해야 합니다. 위 네 열만으로 전체 창을 대체하지 않습니다. 특히 3일 조건에 7일 지연값을 추가하면 3일 바깥의 정보가 들어가므로 별도 승인 없이 추가하지 않습니다.

## 남은 확인

경기 상태는 `note`만을 근거로 사용하며 `gamecenter_status`는 신뢰하지 않습니다. [상태 판단 원칙](../reports/note_status_policy.md)을 따릅니다. 취소일을 모델 입력으로 사용할 때의 당시 가용성은 별도 검증 대상입니다.

후속 [ZIP 검사](../reports/crawl_archive_review.md): 연도별 실행 확인. 2024~2025년 3~10월 JSON 16개에서 재추출한 326건이 전달 CSV와 일치했습니다. 저장 응답에서 CSV로의 누락은 없었으나 미확인 날짜·당시 일정 가용성은 여전히 별도 확인 대상입니다.

추가 팀원 답변과 노트북 검토는 [수집 근거 검토](../reports/crawler_evidence_review.md)에 기록했습니다. 시범경기 제외, 취소 기록 유지, 연기·재편성 연결 미정리가 확인되었습니다. 추가 Excel은 URL만 사용하며 취소 표시를 상태 근거로 쓰지 않습니다.

수집 코드·기간·대회 범위, 실패 처리, 공식 일정 대비 완전성, 취소·변경의 예측 당시 가용성은 아직 확인이 필요합니다. 컬럼 의미 확인만으로 검증 플래그를 1로 바꾸지 않습니다.
